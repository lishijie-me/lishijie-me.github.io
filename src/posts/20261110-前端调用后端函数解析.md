## 什么是回调

> 回调 简单来说就是：“做完这件事后，请执行我给你的这个函数”

### 生活场景类比

1. 你点完菜 (发起请求)
2. 服务员说：“菜好了叫你” (注册回调)
3. 你去忙别的事 (继续执行其他代码)
4. 菜好了，服务员喊你 (回调被触发)

### 为什么最推荐 async/await?

| 特性 | 回调 | Promise | async/await |
| :--- | :--- | :--- | :--- |
| 代码可读性 | ❌ 嵌套地狱 | ✅ 扁平结构 | ✅ 像同步代码 |
| 错误处理 | ❌ 分散在各处 | ✅ 统一的 catch | ✅ try/catch |
| 调试体验 | ❌ 困难 | ❌ 中等 | ✅ 轻松打断点 |
| 条件逻辑 | ❌ 复杂 | ✅ 可行 | ✅ 自然直观 |
| 并行请求 | ❌ 几乎不可能 | ✅ Promise.all | ✅ await Promise.all |
| 学习曲线 | ✅ 简单 | ✅ 中等 | ✅ 最自然 |

### async/await 方式 - 像同步代码一样

```javascript
async function getUserData() {
  try {
    // 看起来就像同步代码！
    const user = await jumpRequestPromise('/api/user', {}, {id: 1}, null);
    console.log('获取用户成功');

    const orders = await jumpRequestPromise('/api/orders', {}, {userId: user.id}, null);
    console.log('获取订单成功');

    const products = await jumpRequestPromise('/api/products', {}, {orderIds: orders.map(o => o.id)}, null);
    console.log('获取商品成功');

    return products;

  } catch (error) {
    // 统一的错误处理
    console.error('请求失败', error);
  }
}
// ✅ 最清晰：代码从上到下执行
// ✅ 最易读：就像写同步代码一样
// ✅ 最易维护：可以轻松插入新逻辑
```
